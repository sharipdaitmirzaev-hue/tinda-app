# Техническое задание — ТИНДА (сокращённый Э1)

## 1. Продукт

**ТИНДА** — адаптивное веб-приложение для оптовой компании: продажа и доставка напитков (далее — и других товаров) в Махачкале и Республике Дагестан.

**Цель Э1:** клиент регистрируется, после подтверждения менеджером собирает заказ из каталога **без цен** и отправляет его; менеджер видит заказ и подтверждает; руководитель работает через те же экраны с расширенными правами.

Язык интерфейса: русский. Валюта (на будущее): российский рубль. В Э1 цены клиенту не показываются и в API не отдаются.

## 2. Окончательные технические решения

| Решение | Значение |
|---------|----------|
| База данных | PostgreSQL |
| Фреймворк | Next.js (App Router), один монолит |
| Язык | TypeScript |
| ORM | Prisma 6 |
| Валидация | Zod |
| Стили | Tailwind CSS |
| Авторизация | безопасная httpOnly cookie + таблица `sessions` |
| Роли | `client`, `manager`, `director` |
| Цены в Э1 | отсутствуют |
| Адреса клиента | один адрес (`clients.address`) |
| Сотрудники | создаются вручную через `prisma/seed.ts` |
| Клиент | видит только свои данные |
| Менеджер | видит своих клиентов и их заказы (или всех при `can_view_all_clients`) |
| Руководитель (`director`) | видит всё |

Имена полей БД, Prisma, API и JSON — **английский `snake_case`**, совпадают между слоями. Русский язык — только в пояснениях и UI.

## 4. Роли и доступ

Проверка доступа — **только на сервере**. Скрытие кнопок в UI не считается защитой.

### Матрица (Э1)

| Субъект | Разрешено | Запрещено |
|---------|-----------|-----------|
| Гость | login, register, cities, health | клиентские и staff разделы |
| Client `pending` / `rejected` / `blocked` | `/pending`, logout, registration-status | каталог, корзина, заказы, staff |
| Client `approved` | каталог, товар, корзина, checkout, свои заказы, профиль | staff |
| Manager | staff/orders (своя область), registration-requests | клиентская корзина/checkout; каталог без `can_edit_catalog` |
| Manager + `can_view_all_clients` | все клиенты/заказы | права director (назначение любого manager и т.п.) |
| Director | все staff-данные, каталог, назначение manager | клиентская корзина/checkout |

### `client`

- Регистрация → статус `pending` → после `approved` доступ к каталогу и заказам.  
- Видит только свои заказы и свою корзину.  
- Может изменить или отменить заказ только в статусе `new`.  
- Не получает `manager_comment`, `password_hash`, цены.

### `manager`

- По умолчанию: клиенты с `manager_id = текущий user.id` и заказы, где `orders.manager_id` или `client.manager_id` = он.  
- При `can_view_all_clients = true` — все клиенты и заказы (расширение видимости, не роль director).  
- Подтверждает / отклоняет заявки; при approve закрепляет клиента за собой (`manager_id` из body игнорируется).  
- Редактирует каталог только при `can_edit_catalog = true`.  
- Фильтры `manager_id` не расширяют область для обычного manager.

### `director` (руководитель)

- Все клиенты и все заказы.  
- Каталог всегда доступен на редактирование.  
- Назначает активного `manager` клиенту/заказу (в том числе `null`).  
- Сотрудники в Э1 не управляются через UI — только seed.

Один пользователь может иметь несколько ролей (`user_roles`). Staff всегда приоритетнее клиентского shop-доступа.

## 5. Регистрация клиента

### Обязательные поля (API / БД)

`company_name`, `inn`, `city_id`, `contact_name`, `phone`, `email`, `address`, `password`, согласие на персональные данные (`pdn_accepted_at`).

### Необязательные

`kpp`, `legal_name`, `legal_address`, `comment`, `extra_phone`, `client_type`.

Без статуса `approved` клиент не оформляет заказы.

## 6. Каталог и карточка товара

Поля товара: `sku`, `name`, `brand`, `category_id`, `volume_text`, `package_type`, `units_per_package`, `sale_unit`, `min_order_qty`, `allow_piece_sale`, `description`, `availability`, `is_promo`, `is_new`, `is_hit`, `image_url`, `is_active`.

Цены в Э1 нет.

Наличие: `in_stock` | `on_order` | `out_of_stock`.  
`out_of_stock` — нельзя добавить в корзину; `on_order` — можно с пометкой.

## 7. Кратность упаковки

- По умолчанию количество кратно `units_per_package`.  
- При `allow_piece_sale = true` шаг = 1.  
- `qty >= min_order_qty`, целое число.  
- При ошибке — предупреждение и ближайшее допустимое `suggested_qty`; отправка заказа блокируется.

Подробности — в `docs/api.md` и `docs/database.md`.

## 8. Заказ

Поля оформления: товары и `qty`, комментарий, `desired_delivery_date`, адрес (из профиля или переопределение в заказе), `contact_name`, `contact_phone`, `payment_method`, `is_urgent`.

Статусы Э1: `new` → `confirmed` → `delivered` | `cancelled`.

После подтверждения изменения вносит только менеджер / руководитель.

## 9. Регион

Э1: Махачкала и Республика Дагестан. Справочник `cities` без зон доставки.

## 10. Инфраструктура (на будущее после Э1)

VPS в РФ, SSL, ежедневный backup, домен вида `app.tinda.ru`, почта `noreply@`, `orders@`, `support@`. В шагах Э1.0–Э1.1 деплой не обязателен.

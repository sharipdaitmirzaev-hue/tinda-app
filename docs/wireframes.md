# Текстовые wireframes — ТИНДА Э1

Русский язык — в текстах интерфейса. Идентификаторы полей и API — `snake_case` (см. `docs/api.md`).

## Общие состояния

- **Загрузка:** скелетон или спиннер, кнопки неактивны.  
- **Пустой список:** короткий текст + действие (если уместно).  
- **Ошибка:** сообщение + «Повторить».  
- **Нет прав:** «Недостаточно прав для этого действия».

Роли: клиент (`client`), менеджер (`manager`), руководитель (`director`).

---

## A1. Вход

**Назначение:** вход в систему.  
**Доступ:** гости.

**Поля UI → API:** email или телефон → `login`; пароль → `password`.

**Кнопки:** «Войти»; ссылка «Регистрация для клиентов».

**Проверки:** обязательные поля; неверный логин/пароль — общее сообщение; `blocked` — доступ запрещён; `pending` — переход на экран ожидания.

**Отложено:** восстановление пароля.

**Переходы:** успех → каталог (клиент `approved`) / заказы (сотрудник) / ожидание (`pending`).

---

## A2. Регистрация клиента

**Назначение:** заявка компании-клиента.  
**Доступ:** гости.

**Обязательные поля:** название компании (`company_name`), ИНН (`inn`), город (`city_id`), контакт (`contact_name`), телефон (`phone`), email (`email`), адрес (`address`), пароль (`password`), подтверждение пароля, согласие на персональные данные (`pdn_accepted`).

**Необязательные:** `kpp`, `legal_name`, `legal_address`, `comment`, `extra_phone`, `client_type`.

**Кнопки:** «Отправить заявку»; «Уже есть аккаунт — Войти».

**Сообщения:** заявка отправлена; ИНН/email заняты; нужно согласие на персональные данные.

**Переход:** экран ожидания подтверждения.

---

## A4. Ожидание подтверждения

**Доступ:** клиент со статусом `pending` или `rejected`.

**Содержание:** статус клиента; текст, что заказы недоступны; при `rejected` — `rejected_reason`; контакты поддержки.

**Кнопки:** «Выйти»; «Обновить статус».

---

## B1. Каталог

**Доступ:** клиент `approved`.

**Элементы:** поиск (`q`), категории, фильтры наличия и меток (`availability`, `is_promo`, `is_new`, `is_hit`), сетка карточек товара (без цен).

**Кнопки:** открыть категорию / карточку товара; «В корзину».

**Пусто:** «Товары не найдены».

---

## B2. Категория

Как каталог с заголовком категории и подкатегориями (`parent_id`).

---

## B3. Поиск

Строка поиска по `name`, `sku`, `brand`. Пусто: «По запросу ничего не найдено».

---

## B4. Карточка товара

**Поля:** фото, наименование, бренд, артикул, категория, объём, упаковка, шт. в упаковке, единица продажи, мин. заказ, описание, наличие, метки, выбор количества.

**Кнопки:** «В корзину»; «Назад».

**Проверки:** кратность, минимум, наличие ≠ `out_of_stock`.

**Сообщение:** «Количество должно быть кратно N. Ближайшее значение: X.»

---

## B5. Корзина

**Список позиций:** товар, количество, ошибка кратности/`suggested_qty`, удаление.

**Кнопки:** «Оформить заказ»; «Продолжить покупки»; «Очистить корзину».

**Пусто:** «Корзина пуста» + «В каталог».

Цены и суммы не показываются.

---

## B6. Оформление заказа

**Поля:** состав (обзор), адрес (по умолчанию из профиля), `desired_delivery_date`, `contact_name`, `contact_phone`, `payment_method`, `is_urgent`, `client_comment`.

**Кнопки:** «Отправить заказ»; «Назад в корзину».

**Проверки:** обязательные поля; дата не в прошлом; все позиции корзины валидны; статус клиента `approved`.

---

## B7. Успешная отправка

Номер заказа (`number`), статус `new`, кнопки «К заказу» / «В каталог» / «Мои заказы».

---

## B8. История заказов клиента

**Фильтры:** `status`.  
**Список:** `number`, дата, статус, дата доставки, срочность, адрес (кратко).  
**Пусто:** «У вас пока нет заказов».

---

## B9. Карточка заказа клиента

Состав, статус, история статусов, контакты, оплата, комментарии.

**Кнопки при `new`:** «Изменить»; «Отменить заказ».  
**Всегда:** «Назад к списку».

**Отложено:** PDF, повтор заказа.

---

## C6. Заявки на регистрацию

**Доступ:** `manager`, `director`.

**Список:** компании в статусе `pending` (фильтр `rejected` опционально).

**Карточка заявки:** все поля регистрации.

**Действия:** «Подтвердить доступ» (`manager_id`); «Отклонить» (`rejected_reason` обязателен).

---

## C1. Список заказов (сотрудник)

**Фильтры:** `status`, срочные, период, клиент.  
**Менеджер** — зона видимости; **руководитель** — все.

**Клик** → карточка заказа менеджера.

---

## C2. Карточка заказа менеджера

Подтверждение, отмена (с причиной), «Доставлен», правка состава/`qty`, комментарий менеджера.

---

## C7–C9. Управление каталогом

**Доступ:** `director` или `manager` с `can_edit_catalog`.

Список товаров и категорий; создание/редактирование товара (поля карточки товара + `allow_piece_sale` + `is_active`); дерево категорий.

**Отложено:** импорт Excel.

---

## Навигация Э1

### Клиент `approved`

```
Каталог → Категория / Поиск / Карточка товара
Корзина → Оформление → Успех
Заказы → Карточка заказа
Выход
```

### Клиент `pending` / `rejected`

```
Ожидание подтверждения → Выход
```

### Менеджер / руководитель

```
Заказы → Карточка заказа
Заявки → Подтверждение / отклонение
Каталог (товары, категории) — по правам
Выход
```

Руководитель использует те же экраны с полным доступом к данным.
